# Architecture review · 27-Oct-2026

Complete review of the tree (TypeScript, server, Python engine and documentation)
with a product goal: **a DAW with an agent that is a professional composer and producer,
and that understands anyone in their language**. All the work is
on the `revision-arquitectura` branch; the work that was uncommitted (importing
MIDI and dragging files) goes in its own commit, at the beginning of the branch.

---

## 1. The diagnosis in one sentence

The domain was well thought out (`Project` + 17 transactional ops validated with zod,
music theory with tests), but **the agent had no access to it**: it could not read the
project, nor write a note, nor add an effect. To compose it wrote a Python
script that generated a `.mid` and then imported it. Hence the 15-20
step turns, the failures that threw away all the work and the pending "score
as data" proposal.

**Score as data already existed**: it is `proyecto.json` plus the ops. What was missing
was giving it to the agent. That is the main thing that changes in this review.

## 3. What changes in the architecture

### 3.1 The agent composes in the project (new tools)

| tool | what it does | where |
|---|---|---|
| `leer_proyecto` | actual state with ids: tempo, key, tracks, effects with parameters, clips; with `clip`, its notes | `src/core/resumen.ts` |
| `editar_proyecto` | **the domain's 17 ops, as is**: transactional, validated, undoable. The ops cheat sheet in the description **comes from the zod schema** (`firmasDeOps`): a new field appears on its own | `src/core/ops.ts` |
| `escribir_progresion` | chords (chord symbols) or scale degrees → notes, with voice leading and block / pulse / arpeggio / alberti / bass patterns | `src/core/composicion.ts` (uses `theory.ts`, which was unconnected) |

Before: 4 chords = write script → run → (fix) → import `.mid`.
Now: 1 call, visible in the piano roll, Ctrl+Z.

### 3.2 Multilingual: the LLM is the translation layer

The rule is simple and applies in every tool: **the tools speak a canonical vocabulary
and the model translates**. This is how anyone is understood without
maintaining dictionaries for 50 languages:

- sound words are an `enum` in the `crear_sonido` schema; the description
  asks the model to translate "punchy", "kurz" or "短い";
- `buscar_sonido` takes the query in Spanish or English (the index's two languages) and
  the model translates the request;
- chords in chord symbols, modes in English (`minor`, `dorian`) and effect and
  instrument types as `enum`;
- project, track, clip and sound names in any alphabet (`slugDe`).

The interface has an i18n base (`web/src/i18n.ts`): Spanish and English, depending on the
browser. **Pending**: the notices that `main.ts` writes in the chat are still in Spanish.

## 5. What remains, in order of importance

### For the agent to be a real producer

1. **Real units in effects** (Hz, dB, ms, ratio) instead of 0..1. A producer
   thinks "cut at 120 Hz", not "cutoff 0.12". The model is the piece that
   asks for it; `DEVICE_PARAMS` and `mapping.ts` are the two places to touch.
2. **A single transport and a single mixer**. WAVs longer than 30 s play through
   `<audio>` synchronized with the openDAW clock: outside its mixer, without track
   or master effects, and at risk of drift. Options: audio streaming inside
   openDAW, or bouncing long stems to a format that openDAW loads in chunks.
3. **For the agent to hear what it does**: `medir_mezcla` (bounce with
   `OfflineEngineRenderer` + `verificar_audio`) so that the mix is decided with
   numbers from the sum, not from isolated stems. Phase 1 of `PLAN.md`.
4. **Buses and sends** (`AuxSendBox`) and automation.

### For it to be a product

5. **Isolation**. Today the agent runs Python with the permissions of whoever starts
   `npm run dev`, on their disk. For any external user a
   sandbox is essential (container per session, or the engine as a service with a closed API
   instead of "run any script"). It is the biggest change and it conditions the rest.
6. **A real server**. The API lives inside Vite's dev server (if
   `server/` is edited, it restarts and kills the turn in flight). With this review's
   split, `server/api/*.ts` can already be mounted on its own HTTP server without
   touching the routes.
7. **The agent loop on the server**. Today it lives in the tab: closing it kills the
   turn. Moving it to the server allows long turns, resumption and several clients.
8. **A single synthesis engine**. `codigo/` (numpy) and `gpu/` (torch) implement the
   same timbres twice; the server even has to reject numpy scripts
   on the GPU. In the medium term, a single voice definition with two backends.
9. **i18n for the chat notices** (`main.ts`): use `t()` from `i18n.ts`.
